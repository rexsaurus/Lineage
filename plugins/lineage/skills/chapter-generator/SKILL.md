# Chapter Generator

**Story units first; chapters are generated.** Each story is one unit file with its source
excerpt, metadata and shaped narrative (content-separator). Chapters are built from units
by the approved chapter map, so a story can move to another chapter by changing one line
of metadata and re-assembling, without rewriting anything.

**The one rule:** never hand-edit `chapters/NN-*.typ` files that carry the GENERATED header.
Change the unit or `data/chapters.csv` and re-assemble; otherwise the next rebuild silently
throws the change away.

Reads: `data/chapters.csv` (approved at the chapter-map gate), `content/units/*.md`,
`book.yaml`, `facts/timeline.csv`, memoir-style-guide (voice and chapter shape) and, for
the family part, family-history-chapters.

## 1. Assign units
Set `chapter` and `order` in each unit's frontmatter:
- **Family part:** units whose `section` is a relative go to that relative's chapter (one
  chapter per named relative, titled with the name); relatives with only a unit or two go
  to **"Others in the Family"**, keeping `section` so each gets a `==` heading. Oldest
  generation first. Each family chapter ends with its apparatus unit (`kind: apparatus`:
  THE RECORDS and the photographs page).
- **Life part:** by date. **Strict chronology inside a chapter**: no flash-forwards, no
  cutting back and forth; a story told *to* the subject goes where they heard it.
- A retold story appears once.
- A unit that fits nowhere stays unassigned and goes on the author's list, never dropped.
```bash
python .claude/skills/chapter-generator/scripts/assemble.py --list   # every chapter's units, plus orphans
```

## 2. Chapter-level fields (`data/chapters.csv`)
| column | use |
|---|---|
| chapter / number | order; printed number (defaults to `chapter`) |
| file | `chapters/03-the-mill-years.typ` |
| title | relatives' chapters: just the name |
| setting, dates | the place-and-years line under the title ("Millbrook, Ohio" · "1934–1952"; `dates` falls back to `date_range`) |
| summary_line | short poetic line in the old-book manner ("On Looms, Floods and Such"); not a list |
| epigraph, epigraph_source | optional public-domain epigraph, verified (style guide §2b) |
| columns | `1` for narrative chapters, `2` for research-dense ones (per chapter) |
| contents | optional "in this chapter" line of short plain nouns from the chapter's units; printed only if `book.yaml` → `print.in_chapter_contents: true` |

The `summary` column (2–4 neutral sentences) is for the spreadsheet and introduction, not
the opener.

## 3. Assemble
```bash
python .claude/skills/chapter-generator/scripts/assemble.py        # all chapters
python .claude/skills/chapter-generator/scripts/assemble.py 5 6    # just these
```
Each chapter file starts:
```
#import "/book/template.typ": *
// GENERATED by chapter-generator …
#show: chapter.with("The Mill Years", number: 3, setting: "Millbrook, Ohio",
  dates: "1934–1952", summary: [On Looms, Floods and Such],
  epigraphs: (([Exact public-domain line.], "Author, Work"),), columns: 1)
```
then each unit's Shaped text in order, `== Name` headings when a chapter holds several
relatives, `#sectionbreak` (❧) between units unless a unit sets `break_before: false`, and
each unit's `lead_in` as a `#bridge[...]` until the author approves it
(`lead_in_approved: true`). The first unit's first paragraph uses `#opening[..][..]` (drop
cap). The opener always starts on a recto with no running head (the template does this).

## 4. Seam pass
Read each assembled chapter start to finish, as a reader would. Fix problems **in the
units**, then re-assemble:
- Two units that are one continuous telling → `break_before: false` on the second.
- A confusing jump → a short `lead_in` of plain transition (no new facts); anything
  interpretive stays a bridge.
- Repeated setup at the start of consecutive units → trim in the later unit.
- Check the shape (style guide §6): opens on the place and people, sections each start with
  when and where, ends on a closing paragraph (then THE RECORDS if context was used).
- It should read as one narrative, not a string of anecdotes.

## 5. Check and report
```bash
python .claude/skills/chapter-generator/scripts/assemble.py --list
python .claude/skills/content-separator/scripts/units.py coverage
```
Then build a draft (`make -C "$LINEAGE" draft PROJECT="$PWD"`) and look at every chapter
opener. Report per chapter: units, words, quotes per page, pending bridges, `// REVIEW:`
flags, and unassigned units.
